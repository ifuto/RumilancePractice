# 仮実装は禁止。必ず完成させる

**途中まで・委譲だけ・ダミーの画面を作って終わり、を禁止する。**

- 「既存画面を開くだけのハブ」「後で繋ぐ前提のボタン」「TODO コメントで済ませた分岐」は
  完成ではない。**機能が実際に動くところまで作る。**
- ある機能を画面に置くと言ったら、その機能の**データ層・コマンド・画面・lang**まで
  一通り揃って初めて「 done 」と言える。
- どうしても外部要因で完結できない場合は、**完了扱いにせず**未了として明示し、
  ユーザーに判断を仰ぐ。黙って仮のものを置かない。
- 部分的にでも動くものを出すなら、それは「完了」ではなく「途中」と明記する。

# 作業の進め方

- **画面ごとに作業する。** 全体設計を論じるより、1画面ずつ作って見せる。
- **過去の経緯に引っ張られすぎない。** 長い説明・過去の経緯の羅列は不要。
- ユーザーは日本語で書く。**返答も日本語で、短く。**
- 「Continue」と言われたら止まらずに作業を進める。途中で確認のために止めない。

# 変更したら必ずバージョンを上げて CI

- 変更ごとに `gradle.properties` の `version` を上げる（通常パッチ +1）。
  上げ忘れたまま CI を通さない。docs だけのコミットも例外にしない。
- **ローカルではコンパイルできない**（paper-api が取得できない）。
  検証手段は CI（`.github/workflows/build.yml`）のみ。
  1. push → 2. `gh run watch <id> --exit-status --interval 15` → 3. 失敗したら直して再 push。
- 完了条件は「CI が緑」ではなく、**CI が緑でかつ JAR が出ていること**。

# 実装上の約束

- **lore / タイトルは簡潔に。文章を使わない。**
  状態＋短いヒント1行まで。説明文を書かない。
- **`docs/design/gui.json` が唯一の情報源。** 過去のレイアウト判断は無効。
- **UI を置くセルがない画面に無理に詰めない。** 入れる場所がないなら別の画面に置く。
- **レコードに項目を足したら、同じパスで `src/test` の arity も直す。**
  `compileJava` は通るのに `compileTestJava` が落ちる典型。
- **`UiTheme.line()` / `UiTheme.hint()` は `Component` ではなく `String` を取る。**
  `Component.text(...)` を渡すとコンパイルエラーになる。
- **トップレベル YAML セクションを足すときは、直前セクションの最後のキーをアンカーにしない**
  （そのセクションの中に入ってしまう）。**次のトップレベルキーの直前に挿入する。**
  切り出すときは既知のキー集合で正確に切る（インデント幅の汎用スキャンは他を巻き込む）。

# 進行管理

- やることリストを **`docs/design/TODO.md`** に維持し、`/tmp/todo.md` にもミラーする
  （`/tmp` はスナップショットされないため、必ずリポジトリ側が正）。
- 実装したら **実装メモ**を TODO に残す（どのファイル・どの設定キー・なぜその形か）。

# 環境の癖

- **再クローンでローカルの履歴がベースコミットまで巻き戻ることがある**（push が
  non-fast-forward で拒否されたらこれ）。復旧手順:
  ```
  git fetch origin
  git reset --soft origin/<branch>     # 変更は staged のまま残る
  git diff --cached --stat             # 変更が生きているか確認
  git commit && git push origin <branch>
  ```
  `git rev-list --count` で local vs remote を比較して見極める。コミットメッセージより
  カウントを信じる。
- `gh run view --log-failed` は空を返すことがある。その場合は変更した型を `src/test` から
  grep して原因を絞る。
- `get_process_output` の `wait_timeout` は 180 秒が上限。
