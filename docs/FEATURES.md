# N Arena — 機能一覧

Paper 1.21.11 向け Practice PvP プラグイン **N Arena**(プラグイン名 `NARENA`、データフォルダ `plugins/n-arena`)の全機能インベントリです。

## GUI デザイン規範(2026-09-28 完全刷新)

全GUIをゼロから統一リデザインしました:

- **枠ガラス全廃** — すべての装飾枠(周縁・上下段の染色ガラス)を撤去し空気に。
  閉じる/戻るボタンだけは維持
- **木時差式ボタン(DelayedButton)は維持** — MAIN KITS / SUB KITS の分岐ボタンは
  押してから4 tick(約0.2秒)で木のボタン音と共に開く確実動作、GUI閉鎖時の
  プレスキャンセルも集中管理(GuiListener)
- **左右対称レイアウト** — 中央列(col4)を軸にペアをミラー配置(キット2,3↔マップ2,5、
  FT 3,3↔ランクモード3,5 等)。**主役(開始・送信などの主ボタン)は中央付近に集約**
  (送信=最下行中央(4,4)、選択肢中ボタン=行中央3/5列ペア)
- **適度な余白** — 7列グリッドのまま、行全体を使わず中央部を優先。内容のない列は
  ノイズにならないよう空に保つ
- **機能の完全性** — 刷新は表現のみ。キット選択・子キット・フォルダ・マップ・FT・
  ランクトグル・チーム用2段階選択など、従来の操作はすべて残っています
- **/kit は2段階のMAIN/SUB分岐に復帰**: 1画面目=中央ペアのMAIN/SUBカテゴリボタン
  (木時差式)、2画面目=選択カテゴリの7個バンド+行端のページ矢印(対称)

### 全画面リビルド(v1.88.0)の詳細

- **レイアウト語彙の共通化**: `GuiLayout`(新設)が `pair(3,5) / hero(col4) /
  widePair(4±gap) / centredRow(奇数はcol4、偶数は3/4が中央) / band(cols1-7固定窓)` を
  定義。画面側に生スロット番号を書かせず、ルール変更は1ファイルで完結
- **ページナビの対称化**: `MenuScaffold.pagingButtons` を
  **前[2] — 戻る[4] — 次[6]** の固定3点に統一(ページ番号はボタン名の「1/3」表記に内蔵、
  左右非対称だった単独のページカウンタータイルは廃止)
- **主役中央の強制**: ロビーコンパスはBATTLEを主要行の中央へ、チームハブは
  START(5,4)を中心に invite(5,1)↔tournament(5,7)、auto-split(5,2)↔settings(5,6) の
  ミラー構成に。シールド編集は remove(5,2) ↔ back(5,6)、apply(5,4) をヒーロー配置
- **設定画面の列ミラー**: オリジナルキット設定は4列1,3,5,7(1..7ウィンドウ)、
  ボット難易度の詳細パラメータは1,3,5,7の4列ミラー、下3行目は中央3点に収束
- **作図バグ修正**: シールドパターンGUIの「次ページ」矢印が存在しない列9に
  配置され(実際は(1,0)へはみ出し)パターンも9列幅で環状していたのを、7列ウィンドウに
  修正(27枚/ページ、行はみ出しなし)
- **リスト画面は7列ウィンドウ(cols1-7)で統一** — 既に一貫していたキット/マップ/
  プレイヤー/履歴/統計系リストはフレーム側の共通規約のみ適用

## 対戦・ゲームモード

### デュエル(決闘)

- `/duel` — 1v1 決闘の申請。`/accept` `/deny` `/cancel`
- **申請GUI(DuelRequestGui)は左右対称の新設計**(2026-09-28 完全刷新):
  相手の頭(0,4)・キット(2,3)/マップ(2,5)・FT(3,3)/ランクモード(3,5)と中央列の周りに
  ミラー配置し、最後に **送信(開始)ボタンを下段中央(4,4)** に集約。キャンセルは左隅(4,0)
- **FT(先取点数)**: クリックで+1、Shift+クリックで+5、40→∞(無制限)→1のサイクル。
  **BO(ベストオブ)は撤廃 — 1試合制のみ**(GUIからBOタイルを削除、内部的にも常に1固定)
- 子キット選択(InnerKitSelectGui)連携: キットをフォルダ化した場合、選んだ子キット名が
  送信GUIに出て、そのまま相手へも通知される
- マップ選択GUI(DuelMapSelectGui)、決闘ID・決闘ログの永続化(duel パッケージ)

### キュー
- `/queue` `/ranked` `/unranked` — ランク戦 / アンランク戦キュー
- キット別キュー、キュー有効/無効、メンテナンスモード
- Ping 上限(ランク戦)、プラットフォーム分離(Java / Bedrock)、自動再キュー
- 待機中は離脱アイテム(赤色の染料)配布 + アクションバー表示
- `/leave` でキュー離脱
- **看板キュー**: ロビーの看板から参加できる Unranked Queue。看板ごとにキット固定(設置時に選択)、カスタム(オリジナル)キット対応。2人目は1人目のキット内容で対戦。看板アイテムは `/practiceadmin sign <kit>`(OP) または管理GUIの「看板キット」から取得して設置

### チーム(パーティ)戦
- `/team` — パーティ作成・招待・参加。最大20人/チーム（1サイド）
- チームハブ・チームカラー(羊毛トグル)・チームマーカー(色付き ●)
- チーム用オリジナルキット戦闘(キット内容=パーティの物、ルール=グローバルキット)
- チームカラーアーマー、敵透過表示抑制(TeamGlowLos)、パーティホットバー
- **自動解散**: パーティは次のどれでも消える(0人のパーティやオーナー不在のパーティが残らない)。
  - **オーナーが `/team leave`** → その場で解散(Queue / Duel 状態も一緒に掃除)
  - **オーナーがサーバーを抜けた** → 解散。ただし**試合中だけ**は進行中の試合を壊さないよう
    「解散待ち」の印を付けて、試合が終わってから解散する
  - **メンバーが0人になった**(最後の1人が抜けた / ログアウトした) → その場で解散
  - 取りこぼし対策として **3秒ごとの定期掃除**(`TeamService.startMaintenance`)が
    「0人」「オーナーが居ない」「解散待ちなのに試合が終わった」パーティを回収する
- **試合中のパーティに入ったら観戦ボタン**: 進行中の**チーム戦**があるパーティに参加すると、
  入った人のチャットに `[観戦する]` ボタンが出る(`/team spectate`)。押すと `SpectatorService`
  経由でその試合を観戦する。**Private FFA はチーム戦ではないので対象外**。自分がその試合の
  出場側の場合や、観戦できる試合が無い場合はボタンもメッセージも出ない。

### FFA
- `/ffa` — 常設 FFA エリア。アリーナ選択・リスポーン・スポーン分散
- デス→ロビー戻り、戦闘ログ
- **`/bot`(FFA内)= マネキン練習台**: FFA アリーナ内での `/bot` は Quantum BOT ではなく
  **マネキン方式のダミー**を出す(`FfaMannequinService`)。
  - **既定 OFF・アリーナ単位の任意 ON**: `/practiceadmin` → FFA Config → アリーナの
    **`FFA Bot`** トグル(`ffa.yml` の `arenas.<id>.settings.bot`)で有効化する。
    OFF のアリーナでは `/bot` はマネキンも Quantum BOT も出さず、どこで ON にするかを案内する
    (新規作成アリーナも OFF)
  - 装備: **不可壊(耐久無限)のネザライトフル装備** — 全身 Protection 4、
    **レギンスだけ Blast Protection 4**。**両手にトーテム**(`TOTEM_OF_UNDYING`)
  - ネームタグ: **太字・水色の `NARENA BOT`**(常時表示)
  - 出現位置: 視線方向 2 ブロック先(自分の方を向く)。アリーナに region があれば内側にクランプ
  - **ダメージは全部そのまま受ける**: クリスタル・リスポーンアンカー・ベッド・TNT・矢・ポーション・
    近接を、**所有者でも他人でも**区別せずバニラの計算どおり通す(攻撃者フィルタも帰属解決も無し)。
    他プラグインがキャンセルした frame は開け直すので、グローバルな保護で無敵化しない
  - **倒せない**: 両手のトーテムでバニラ本来の POP(音+パーティクル+消費→HP半分)が走り、
    直後に両手へ補充。手が空になった場合も死亡を握りつぶして体を再生成
    (キャンセルされた致命傷を生き延びた Mannequin はクライアント側で固まるため)
  - VOID 落下だけはキャンセルして所有者の元へ戻す(アリーナの外へ落ちると二度と戻せないため)。
    3 秒無被撃で毎秒 1 HP 回復(最大 20)
  - **再度 `/bot` で削除**。アリーナの FFA Bot を OFF にした時点・FFA 退出・試合への引き抜き・
    ログアウト・プラグイン停止でも消える(`setPersistent(false)` なのでディスクには残らない)
- **`/bot`(FFA外)= Quantum BOT**: 従来どおり同梱マップの実 BOT をスポーン

### プラクティス
- `/prac` `/practice` — ソロ練習モード。アンカー・TNT・メイスの練習台
- **Battle Menuの「ボット」**(ITEM 44): 5モード選択画面(クリスタル/ネザポット/メイス/
  カートPvP/ソード)。各タイルに運営が紐づけたキット・空き部屋数を表示し、空いている
  部屋へ入室
- **対戦ボット部屋**(ITEM 41/44): `/practice draft <名前>
  <ANKER|MACE|SWORD|CRYSTAL|NETHERITE_POT|CART>`
  → `pos1`/`pos2` → `selection apply` → `p1` → `botpos`(任意) → `save` → `enable`
  - **試合と同じ流れ**(ITEM 44): 待機(時間/難易度/設定)→カウントダウン→戦闘→
    勝利/敗北/引分タイトル→60秒でロビー。複数人の同時Bot戦もセッション単位で独立
  - **キット紐づけ**(運営必須): `/practice bindkit <モード> <キット|clear>` —
    practices.ymlの `bot-mode-kits` に保存。試合開始時に紐づけキットを適用、
    未設定ならモード標準装備(コンソールに警告)
  - **マップ紐づけ**(ITEM 44): `/practice bindmap <モード> <部屋|clear>` —
    そのキットに紐付いたマップ(練習部屋)で試合する(`bot-mode-rooms` に保存)。
    未設定ならモード内の最初の空き部屋
  - **時間制限は10分固定**(600秒)。判定がつかないまま10分経過で引き分け
  - **難易度**(BotDifficultyGui、プレイヤー単位で保存): 配布マップ準拠プリセット
    (NPC/イージー/…/サバイバルマスター)+詳細パラメータ(攻撃力/攻撃間隔/移動速度/
    回復/コンボ間隔/シールドスタン/シールド軽減/トーテム目標)。practices.ymlの
    `bot-difficulty` に永続化。**マップ実数値準拠**(quantum:difficulty/0..6を全行抽出):
    1発の威力は全ラング共通の本物の剣撃(8・バニラ経路)、移動は全ラング走行同等、
    難易度は**攻撃間隔・エイム・回転速度・トーテム間隔**で表現。**Botの最大体力は
    全難易度でプレイヤーと同じ20、攻撃リーチもプレイヤーと同じ3.0ブロック**。
    メイススマッシュの落下スケールはバニラ式そのまま
  - ソードBot: 追跡+左右ストレイフで斬りかかる、シールド構えで被ダメ半減+
    殴り返すとスタン、3秒無被撃で回復(すべて難易度依存)
  - ネザポットBot(ITEM 44): 剣AI+体力50%割れで回復ポーション、近距離の相手に
    有害ポーション
  - カートPvP Bot(ITEM 44): 弓で牽制しつつ距離を取り、着火TNTを転がしてくる
    (配布マップのTNTトロッコモードをアレンジ。爆発源=BotでBotは自爆無効)
  - クリスタルBot: マップg1gc実装に全面準拠 — 2m以内で足止め・超えたら前進(壁はホップで
    登る)、3m以内から**本物の剣撃**(8ダメージ・全難易度350ms固定間隔・プレイヤーの
    無敵時間が切れた時だけ)、crystal_cd梯子(300/300/300/150/100/150ms)で黒曜石台+
    エンドクリスタルのコンボ。**リスポーンアンカーは全難易度で使用**(近接圏外で
    設置→充填→爆発のサイクル: anchor_cd 250/200/200/150/50/50ms→charge_cd
    250/200/150/100/100/100ms→爆発(威力5+着火)→explosion_cd休止・アンカー破壊で
    中断)。トーテムポップ後は**totem_cd梯子分の休止**(Easy 2秒〜Master同tick復帰)。
    HP20・回復は金リンゴのみ(HP80%で手に持って1.75秒実食→+8HP/5s・吸収2・2個/命)。
    プレイヤーが箱囲いすると**頭上/足元の床/間の壁を採掘**(1.5秒/ブロック)。全アクションで
    マップ同様に**ホットバー可視切替+手振り**(剣/クリスタル/黒曜石/アンカー/グロウストーン/
    金リンゴ/パール)。
    勝利条件はトーテムポップ数が目標に到達すること
  - クリスタル/カート部屋は爆発ダメージがプレイヤーにも通る(自クリ誤爆・TNT含む)
- `/practice botpos <名前> [clear]` — アリーナ内のBot出現位置を運営が設定(全Bot種対応)
- 練習ボット設定(PracticeBotGui: シールド切替)、レイアウト編集(PracticeLayoutGui)
- Bot戦の開始/結果と通常試合の結果はコンソールにも記録(`[N Arena][BotMatch]` /
  `[Match]` プレフィックス)
- **AFK練習の入口は1つ**: `/afkcrystal`(`/afkc`)。旧9x9トーテムBOT部屋(`/afkpractice`
  `/afkp`)は廃止され、**`/afkpractice` `/afkp` `/afk` はすべて `/afkc` の別名**として
  同じAFK BOT Crystalの部屋を開く(サブコマンドもそのまま `start|stop|kit|settings|reset`)
- **AFK BOT Crystal**(`/afkcrystal` `/afkc`): クリスタルPvP練習用の新BOTタイプ。
  100x100ネザライト床を自動生成し、BOTはフル装備(ヘルメット/チェストプレート=
  Protection IV、レギンス/ブーツ=Blast Protection IV(最大)、全パーツに火炎耐性+
  耐久無限=Unbreakable、更にFire Resistance無効化)。
  - **常にトーテム**: BOTはトーテムを保持し、致命傷で**バニラ本来のトーテム発動**
    (本物のエフェクト+手から消費+ハート半分で復活)→**即時補充**のため倒せない
    (体力はしっかり減り、名前欄にリアルタイム表示)。万が一死亡が成立しても
    プラグインが死亡を握りつぶしてBOTを即再生成(**BOTが消えることはない**)
  - **オフハンドの盾ON/OFF**(設定GUI `/afkcrystal settings` またはホットバーの
    コンパレータ): ONなら正面の攻撃/投げ物/爆発をバニラ同様ブロック
  - **盾の復帰時間**: 斧で割られた盾が戻るまで **2秒 / 5秒(デフォルト)** を選択可能。
    プレイヤーの盾もBOTの斧で無効化される(バニラ相当)
  - **リセットボタン**: プレイヤースポーン地点中央のボタンで「キット全再装填+
    置きブロックの一掃+BOTの位置・体力・エフェクト・盾の状態を初期化」
    (`/afkcrystal reset` でも可)。**プレイヤーが死亡してもBOTは初期化されない**
    (エリアとキットだけ復元。BOTのリセットはボタン/リキットの明示時のみ)
  - **建築自由(個数・半径制限なし)/ 高さ上限は30ブロック**: アリーナ内ならどこでも
    何個でも設置可。**設置できる高さは床から30ブロックまで**で、それより上は設置だけ
    拒否される。**この30はブロックの設置高さのみの制限で、プレイヤーの移動制限では
    ない**(境界テレポートは廃止。床の外へ出る・高く登るのは自由で、VOID落下だけは
    スポーンへ救助)。
    **リセット(ボタン/リキット/死亡)はアリーナ全面を設置上限(+旧上限分の余裕)まで
    ボタン以外全部空気に一掃**するので置いたブロックは必ず元に戻る。ネザライト床と
    ボタンのみ破壊不可(爆発でも消失しない)。水晶爆発の自傷ダメージは本物通りに通る。
    **ウィンドチャージは地面に向かっても投げられる**(インタラクト握り潰しの再武装)
  - BOT戦とキットの紐づけは2系統: **`/botadmin <SWORD|MACE|CRYSTAL|NETHERITE_POT|CART>
    <キット>`**(装備の紐づけ。例: `/botadmin mace mace`。タブ補完で候補表示。`off`で解除)
    と `/practice bindkit <モード> <キット>`(同一ストアなのでどちらでも可)、
    **`/botadmin <botkit> <arenakit>`**(開催アリーナ側の紐づけ。同一キットも可)。
    引数なしで両方の紐づけ一覧を表示
  - **キット紐づけ(運営)**: `/afkcrystal bindkit <kit|list|clear>` でサーバーキットを
    **最大5個**まで紐づけ(`/afkcrystal unbindkit <kit|all>` で解除、
    afk-crystal-settings.yml に永続化)。紐づけがある間、部屋のキットは**キット選択GUI**
    になり、選択したキットが**試合と同じ方式**(KitLoadout適用)で装備される。
    スポーン中央ボタンの再装填(rekit)・リスポーンでも選択キットが再装備され、
    選択はプレイヤー単位で記憶される。未紐づけなら従来どおり個人キットエディタ
  - AFK BOT CrystalのBOTは**攻撃してこない**(ノックバックで100x100の床どこへでも
    移動する。端に出た時だけ定位置へ戻る)。盾ON時は**常にプレイヤーの方を向き、
    盾を実際に構えるポーズ**(Paper Mannequinのアイテム使用ポーズ)。斧で盾を割った
    打撃分のダメージも通る。体力は**常に20**(バニラ範囲)。浮遊した場合は
    **その場で床に着地**、BOTが消えても自動で再生成。ホットバーの専用スロットは廃止。
    キット=`/afkc kit`、設定=`/afkc settings`
  - **全員別々の専用アリーナ**: 入室ごとに自分の固定アンカー(+60kライン)へ完全
    再生成。死亡時・中央ボタンでも**アリーナごと初期化**(建築も元通り)
  - **落下ダメージ・クリスタル/アンカーの自傷は本物**(落下溜めクリスタルが機能)。
    BOTへのクリスタル爆発も通る(他リスナーがキャンセルしても復活させる)
  - トーテムポップ時も**ノックバック/ウィンドチャージのノックを再適用**(無効化されない)。
    ポップ後は**BOTを再生成**して凍結を防止(キャンセルされた致死ダメージを通した
    Mannequinはクライアントが死亡判定して操作・KBを一切受け付けなくなるため)。
    ポップ直後の体力はハート半分(1HP)。実際にトーテムを持っている致命傷は
    **バニラ本来のトーテム発動**(本物のエフェクト+消費+ハート半分で復活)で、
    死亡ネットにより**BOTが消えることはない**
    入室時に**装備一式を自動配布**(最初の装備適用で破棄されるloaner)
  - `/afkc stop`・`/hub`・`/lobby` で**いつでも中断してロビーへ**(LobbyServiceの
    実ロビー復帰を呼ぶ)
  - **`/hub` `/lobby` `/spawn`でAFKセッションは終了**してロビーへ戻る

  - **入室排他**: FFA参加中・コンバットタグ中・デュエル/試合中・観戦中・キュー中・

## キット・アイテム

- **中メニュー(キットの子メニュー)**: キット一覧にある任意のキットを **「フォルダ」** にできる。
  親タイルは元の名前・アイコンのまま一覧に残り、**左クリックで運営が選んだデフォルトの子キット**、
  **右クリックで子キット一覧**に進む。例: `Axe`(親タイル) → `Axe-default`(元のキット)、
  `Club Axe`、`Hatena Axe`。親そのものの装備で戦うわけではなく、必ず子キットで戦う。
  - **子は普通のキット**: アイテム41スロット、防具・オフハンド・フルNBT、アイコン、表示名、
    最大HP/KB/ブロックルール/アリーナ等の設定、個人レイアウト、ランク戦績まで **子ごとに独立**。
    子は親の右クリック一覧から選び、トップレベル一覧には重複して表示されない。再戦でも
    選んだ子のIDがそのまま引き継がれ、試合は選んだ子のルール・中身で行う。
  - **Queue は子メニューに入れない**: 親タイルは1件のみで、クリック/看板/`/team queue` のいずれも
    デフォルトの子だけを使う。`/queue <子>` を直接入力しても親のデフォルトの子へ正規化する。
    待機人数、ELO、試合の統計キーも実際の子キットIDになる。Queue の右クリックは従来どおり
    **そのデフォルト子のキット内容プレビュー**であり、子キット選択画面ではない。
  - **管理はGUIで完結(Admin専用)**: `/kit` → 親キットを選択 →「中メニュー」、一覧で親を右クリック、
    または `/kit submenu <親>` で管理画面へ。`/ekit` で親を右クリックしたときは一般プレイヤーも
    Admin も子キット選択画面になり、Admin にはそこから「管理」ボタンが出る。
    - **既存の普通のキットを入れる**:「既存キットを中へ移動」→ 対象をクリック。
      キットID・中身・ルール・個人配置・戦績を変えずに所属だけ変更できる。
    - **新しい子を作る**: インベントリを撮影 / デフォルト子からコピー / 空、の3ボタンを選び
      チャットで表示名を入力。新しい子はデフォルト子のルールを起点に作られ、その後は個別に
      設定できる。最初に親をフォルダ化するときは**元の親キットが自動で `親-default` 子にコピー**
      される(元の装備が黙って消えない)。明示的な「フォルダ化」ボタンもある。
    - **子キットの操作**: 左クリックでその子の通常の `/kit` 設定画面(HP・ブロックルール・
      アリーナ・アイコン・表示名等)。Shift+左クリックで全員共通の41スロット編集。
      設定画面の「共通のキットの中身を編集」も同じ機能で、保存先は **kits.yml**。
      `/ekit` の通常エディタは従来どおり **自分の個人レイアウト** を編集する。
    - **デフォルト変更**: 管理画面で子を右クリック。子をフォルダ外へ戻すときは子の設定画面で
      「子メニューから取り出す」。削除は子で Q → 確認GUI。デフォルトの子を外した場合は
      残った先頭の子へ自動で切替。最後の子が無くなると元の親キットに戻る。
  - **テキスト操作(補助)**: `/kit submenu [親]` / `convert <親>` / `add <親> <名前...>
    [--from <player>|--copy|--empty]` / `move <親> <既存キット>` / `remove <親> <子>` (削除ではなく
    外へ戻す) / `default <親> <子>` / `list [親]`。`/kit preset` は互換エイリアスだが、
    **旧プリセットを新規には書かない**。

    子 `kits.<子>.parent: <親ID>`。既存の普通のキットは更新しただけでは変換されず、データは
    そのまま残る。フォルダ化時は親の元の中身・ルールを子に複製し、DB上の個人配置と
    ランク戦績も子へ **追加コピー(元の行はバックアップとして保持・既に子の行があれば上書きしない)**。
    旧 `kits.<kit>.inner-kits.<preset>` が本当に存在するサーバーは起動時に一度だけ
    それぞれを普通の子キットへ移行し、個人の旧 `<kit>#preset#<id>` レイアウトも新しい子IDへ
    引き継ぐ。失敗した場合は旧セクションを残して次回起動時に再試行する。

- **TAB ●残留の修正**: スコアボード表示 OFF (Settings) のプレイヤーは update() を
  通らないため、試合用 TAB 取り込み (playerListName 上書き / リスト順序 / 見えない
  filler行 / listed=false) がロビー復帰後も一生残る不具合を修正。表示 OFF でも
  試合に属さない限り毎 tick クリアを実行。
- **Party Fight 脱落→退出ボタン**: 脱落→同チーム残員を観戦する直後のチャットに
  **「観戦をやめてロビーに戻る」** クリックボタンを表示。実体は /hub →
  leaveEliminatedTeamSpectator で、敗北処理 (ドロップ・勝敗帳) の再実行や罰は発生しない。
- **シュルカー例外 (can_break/can_place_on タグ方式・正当仕様)**: シュルカーボックス (17種) のみ
  **全キット常に設置可能**、破壊は **その試合/FFA で本人が設置したものに限る**
  (アリーナ生成シュルカーは護られる)。forceAdventure キットは引き続き真の ADVENTURE —
  アドベンチャーではクライアントが設置/破壊パケット自体を送信しないため、例外はアイテムの
  NBT (1.20.5+ データコンポーネント can_break/can_place_on, 旧 CanDestroy/CanPlaceOn) で与える:
  持てる全キットアイテムに can_break[シュルカー17種]、シュルカー本体には can_place_on[任意ブロック]
  (空 BlockPredicate = 全ブロック一致)。ツールチップ行は tooltip_display で非表示。
- **同一IPマッチ制限 (ランク戦のみ)**: RANKED で同じ接続元IP同士は絶対にペアにならない
  (キュー + ランクデュエル請求の両経路)。UNRANKED/パーティ戦などの気軽な対戦は対象外。
  `queue.block-same-ip`（既定 true）。
- **KB プロファイル (kb/*.json) と Duel Request の KB 選択 (2026-10-01)**: KB Probe mod
  (0.5.0) のコピーボタンで得られる「その鯖のKB再現数値 JSON」を `plugins/n-arena/kb/`
  に `<名前>.json` として置くと、**Duel Request 画面の KB 選択**（旧ランク/アンランク
  トグルの位置 — デュエル請求は Unranked 固定に変更）にファイル名 (.json除く) が
  選択肢として表示される。選択肢は「**既定 (デフォルトKB)**」→「**KBの変更無し**」→
  各プロファイル名の循環。既定未選択時と Queue/forcematch 等メニューを持たない試合には
  OP設定の **デフォルトKB** (`kb.default-profile`、/practiceadmin kbdefault <名前|off>)
  が自動適用される。適用は試合セッションに保持（rematch も同プロファイルで再現）、
  試合プロファイル &gt; キット &gt; cause &gt; グローバルの最優先レイヤとして
  Paper 最終ベクトルの乗数調整（バニラ計算・耐衝撃は無傷）。
- **高度 Alt アカウント検知 (非公開・管理者のみ)**: 海外文献由来の行動バイオメトリクス—
  戦闘中スイング間隔分布 (mouse-dynamics 系, JS divergence)・JST 接続時間帯分布 (cosine)・
  IP 共有・短時間アカウント切替カデンス—を多層信号として超保守的に融合。無関係ペア母集団の
  最大スコア+マージンで null-floor 自己較正するため「誤検知反応ゼロ」運転を最優先。
  閾値未満は誰も警告されず、RESTRICT (conjunctive evidence: IP共有 or 頻繁切替 or 行動≈恒久一致
  が必須) 超過ペアのみランク戦マッチング制限に自動接続。一般プレイヤー・実力差対戦には
  反応しない設計（自動処罰なし、BAN は一切行わない）。実力差のある健全な対戦に反応しないことを
  保証し、別 IP の同一人物に行動一貫性で反応する設計。管理者は /practiceadmin altflags で
  証拠キューを閲覧・#n で dismiss 可能。`alt-detection.*` (既定 enabled, flag≥70, restrict≥85,
  min-swings≥300, 30分スキャン)。SQLite/MariaDB に alt_ip_history/alt_ipswitch/alt_behavior/alt_flags
  (schema v35)。
