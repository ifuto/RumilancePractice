## 1. 概要

**RumilancePractice** は Paper 1.21.11 向けの **Practice PvP（練習サーバー）プラグイン**です。

- ランク戦 / アンランク戦の **1v1 デュエル**（キュー + 直接申請）
- **FFA** アリーナ
- **ロビー** システム（スポーン・保護・インベントリ・機能アイテム）
- **キット** システム（公式キット + 個人レイアウト編集 `/ekit` + オリジナルキット）
- **FAWE / WorldEdit** によるアリーナ再生成（未導入でも動作）
- Elo レーティング・ランキング・統計・プロフィール
- 観戦・スコアボード・多言語化・ChatBan など

**重要仕様（設計上の要点）**

| 仕様 | 内容 |
|---|---|
| アンランク戦は統計を一切変更しない | `UnrankedResultProcessor` は監査ログ（audit_log）に記録するのみ。Elo / 勝率 / K/D / 公開統計は変更しない |
| GUI の識別 | タイトル文字列ではなく `PracticeGuiHolder`（セッションUUID + GuiType）で識別 |
| 機能アイテムの識別 | 表示名ではなく PDC `function_type` で識別 |
| プレイヤー状態 | UUID キーの `PlayerStateManager` で一意管理（状態機械 + 遷移検証） |
| サーバー停止時の ChatBan | `MatchSession.shuttingDown` 中は切断 ChatBan を発行しない |

## 3. ビルドと導入

```bash
cd RumilancePractice
./gradlew build          # Windows は ./gradlew.bat build
```

成果物: `build/libs/RumilancePractice-1.2.0.jar`

導入:

1. `plugins/` に `RumilancePractice-1.2.0.jar` を配置（**thin ではなく通常版**）
2. （推奨）FAWE / WorldEdit を導入
3. サーバー起動 → 初回起動時に `plugins/RumilancePractice/` へ各 YAML が生成される
4. 管理者セットアップを実施（[§17](#17-管理者セットアップ手順)）

> 初回起動時に `config.yml` 等が無ければ jar 内のデフォルトがコピーされ、既存ファイルは jar 内デフォルトを `setDefaults` として重ねるため、一部だけ書き換えた設定でも新キーが失われません（`ConfigService.loadWithDefaults`）。

## 9. 起動フロー

`RumilancePractice.onEnable()`:

1. `ServiceRegistry` 生成、`ItemKeys.init(this)`
2. `ConfigService.loadAll()`（11 ファイル）→ `PluginSettings.from(config)` スナップショット
3. `AsyncExecutor`（1〜4 スレッド）生成
4. `SessionManager` / `PlayerStateManager` 生成
5. `LocaleService`（`plugins/RumilancePractice/lang` も参照）+ `MessageService`
6. **`initializeDatabase()`**: `DatabaseService` → `SchemaMigrator.migrate()` → 全リポジトリ登録。**失敗時は SEVERE ログの上でプラグイン無効化**
7. `EloCalculator` 生成
8. `FaweBridge` 選択（FAWE/WE 検出 → `FaweBridgeImpl`、無ければ `NoOpFaweBridge` + 警告ログ）
9. `FeatureBootstrap.enable()` → 全サービス・GUI・リスナー・コマンド結線 → 「RumilancePractice has been enabled.」

`onDisable()`: FeatureBootstrap.disable → DB close → AsyncExecutor shutdown(10s) → ServiceRegistry クリア。

`FeatureBootstrap.enable()` の結線順（重要）:

1. `RuntimeFlags`（メンテナンス）登録
2. `SettingsService` → `SoundService` → `LobbyService` → `KitService` → `KitLayoutCache` → `ArenaTemplateStore.reload()` → `ArenaService`（FAWE 有無で切替）→ `GuiSessionRegistry` → `QueueService` → `DuelRequestService`（TTL 60s、レート制限 3s）

4. 全 GUI 生成・`GuiListener` 登録 → `FunctionalItemListener`（開く GUI をセット）
5. `ScoreboardService.start()`（設定が有効なら）
6. リスナー登録: `SessionBootstrapListener` / `LobbyListener` / `MatchListener` / `ArenaBoundsListener` / `FfaListener` / `GuiListener` / `FunctionalItemListener` / `AdminToolListener` / `PracticeSideListener`
7. コマンド結線（`bind()`）: 上記 [§5](#5-コマンド一覧) の通り。`originalkit` はラムダで直接結線

## 10. コアシステム解説

### 10.1 プレイヤー状態機械（`PlayerStateManager` / `PlayerState`）

状態一覧: `IDLE` → `LOBBY` → `OPENING_GUI` / `QUEUED_RANKED` / `QUEUED_UNRANKED` / `REQUESTING_DUEL` / `SPECTATING` / `FFA` / `EDITING_KIT` → `PREPARING_MATCH` → `COUNTDOWN` → `FIGHTING` → `ENDING`

許可される遷移（遷移表）:

```
IDLE            -> LOBBY
LOBBY           -> OPENING_GUI, QUEUED_RANKED, QUEUED_UNRANKED, REQUESTING_DUEL, SPECTATING, FFA, EDITING_KIT
OPENING_GUI     -> LOBBY, QUEUED_RANKED, QUEUED_UNRANKED, REQUESTING_DUEL, SPECTATING, FFA, EDITING_KIT
QUEUED_RANKED   -> LOBBY, PREPARING_MATCH
QUEUED_UNRANKED -> LOBBY, PREPARING_MATCH
REQUESTING_DUEL -> LOBBY, PREPARING_MATCH
PREPARING_MATCH -> COUNTDOWN, LOBBY
COUNTDOWN       -> FIGHTING, LOBBY
FIGHTING        -> ENDING
ENDING          -> LOBBY, PREPARING_MATCH
SPECTATING      -> LOBBY
FFA             -> LOBBY
EDITING_KIT     -> LOBBY
```

- 不正遷移は `IllegalStateTransitionException` を投げる
- `resetToLobby()` は無条件に LOBBY へ（キュークラッシュ / 管理クリーンアップ / リロード時の安全網）
- 仕様上のバグ防止: 二重キュー不可、FIGHTING 中の申請承認不可、クラッシュ後の復帰は強制リセット

### 10.2 セッション（`SessionManager` / `PlayerSession` / `MatchSession`）

- `PlayerSession`: オンライン中のプレイヤーの実行時状態（locale / selectedKit / arrowEffect / currentMatchId / soundsEnabled / scoreboardEnabled）
- `MatchSession`: 1 試合の実行時表現。id / mode / kitName / participants / terrain / bestOf / arenaInstanceId / kills / roundWins / winner / draw / state / rematchRequestedA・B / shuttingDown
  - 冪等ガード: `tryMarkResultApplied()`（結果二重適用防止）、`tryMarkDisconnectPenalty()`（切断ペナルティ一回のみ）

### 10.3 ロビー（`LobbyService` / `LobbyListener`）

- `sendToLobby`: アドベンチャーモード、HP/食料回復、火・落下リセット、飛行解除、エフェクト除去、ロビーインベントリ適用、スポーンへ `teleportAsync`（WorldBorder セーフ位置へクランプ）
- `applyLobbyInventory`: 保存された 41 スロット（36 インベントリ + 4 防具 + オフハンド）を適用
- `setSpawn` / `setRegion` / `saveLobbyInventory` / `isConfigured` / `validate`（スポーン・領域・包含・ボーダー検査）
- `LobbyListener`: LOBBY / OPENING_GUI / QUEUED_* / REQUESTING_DUEL / IDLE 状態のプレイヤーを保護
  - ダメージ（落下・近接・投射物）キャンセル、空腹固定、ブロック破壊/設置キャンセル（`rumilance.lobby.bypass` で回避）、アイテムドロップ/ピックアップ制御

### 10.4 キュー（`QueueService` / `QueueCoordinator`）

- `QueueService`: キット×モード別のキュー。`QueueEntry(playerId, kitId, mode, elo, joinedAt, ip)`
  - `join()`（FFA 拒否・二重入場拒否）/ `leave()` / `pollMatches(blockSameIp, avoidRecent, now)`
  - `canMatch`: 同プレイヤー不可、同一 IP ブロック（設定フラグ）、直近対戦相手回避（設定フラグ）、アンランクは無条件、ランクは **初期 Elo 幅 75 + 15秒毎に 25 拡大**
  - `recentOpponents`: 直近対戦を記憶
- `QueueCoordinator`: 40 tick 毎にマッチング → `matchService.startDuel(...)`。20 tick 毎にアクションバー（待ち時間・待機人数）
  - `join()`: メンテナンス・キット無効・状態不正・二重入場を拒否 → Elo 取得（失敗時 1000 にフォールバック）→ キュー投入 → `QUEUED_RANKED/UNRANKED` 遷移 → 失明エフェクト 40tick → Leave Queue アイテム（RED_DYE, スロット4）付与 → サウンド・メッセージ
  - `leave()`: キュー離脱 → LOBBY リセット → ロビーインベントリ再適用

### 10.5 デュエル申請（`DuelRequestService` / `DuelCommand` / `DuelRequestGui`）

- `create(sender, target, kit, ranked, terrain, bestOf)`: TTL 60 秒、送信間隔 3 秒のレート制限、自己申請拒否
- 承認: `/accept` → `matchService.startDuel(...)`（ランク/アンランク、terrain、bestOf）
- 申請通知: チャット + `[CANCEL]` / `[ACCEPT]` / `[DENY]` クリック可能ボタン
- マッチ開始時に両者の保留申請を無効化（`invalidateForPlayer`）
- `DuelRequestGui`: 相手の頭（ping / 戦績 / K/D 表示）、キット選択・マップ選択・モード切替・Best of (1/3/5)・送信

### 10.6 マッチ進行（`MatchService` / `MatchRegistry` / `MatchListener` / `ArenaBoundsListener`）

`MatchState` 遷移: `CREATED → RESERVING_ARENA → PASTING_ARENA → WAITING_FOR_PLAYERS → COUNTDOWN → ACTIVE → ENDING → CLEANING → CLOSED`（失敗時 `FAILED`）

フロー:

1. `startDuel`: 二重登録チェック → Kit 有効チェック → `MatchSession` 作成 → `MatchRegistry.register`（プレイヤー・アリーナ二重防止）→ 申請無効化 → `PREPARING_MATCH` 遷移 → **MATCH FOUND タイトル + ジングル** → `arenaService.reserve(DUEL, terrain, matchId)`
2. アリーナ確保失敗 / 二重予約 → `failMatch`（「No arena available」等の理由付きメッセージ）
3. `WAITING_FOR_PLAYERS` → 0.5 秒後に両者を `teleportAsync`（両方成功するまで待つ）→ キット適用（個人レイアウト読み込み）→ `startCountdown`
4. カウントダウン: アクションバーに残り秒数 + サウンド → `beginFight`: `ACTIVE`、`FIGHTING` 遷移、スポーン再配置、FIGHT! タイトル、タイムアウトスケジュール
5. タイムアウト: kit.timeoutSeconds > 0 ならその値、無ければ max-duration-seconds（0=無効）。時間切れは引き分け
6. `handleLethal`（MatchListener がイベントをキャンセルして呼ぶ）: 自滅は引き分け、それ以外はキラー勝利 → `endMatch` → 結果プロセッサ → リマッチアイテム（LIME_DYE スロット3 / RED_DYE スロット5）→ エンド演出
7. `endMatch` 後: 勝敗タイトル / サウンド / Elo 変動メッセージ / 指定秒後にロビー帰還（`returnPlayersToLobby`）→ **auto-requeue 設定なら 10 tick 後に自動再キュー**
8. 再戦: 両者がリマッチ要求（`bothRematchRequested`）→ 別アリーナで `startDuel` 再実行

切断（`handleDisconnect`）:

- ACTIVE 前に切断 → `failMatch`（カウントダウン/準備中含む）
- ACTIVE 中に切断 → 相手勝利。`rumilance.punishment.bypass` を持たなければ **切断 ChatBan（既定 7 日）** を発行（shuttingDown 中は発行しない）
- `reconnect-grace-seconds` は現状フラグのみ（猶予実装は未接続）

`/leave`（`leaveDuringCountdown`）:

- COUNTDOWN 中のみ離脱可能。試合キャンセル（結果記録なし、双方 LOBBY へ）
- 連続カウントダウン離脱ストリークを記録（`countdownLeaveStreak`）。**3 回目で 3 日 ChatBan**。FIGHT 到達時にストリークリセット

`MatchListener` の戦闘ルール:

- COUNTDOWN / ENDING 中はダメージ無効、ACTIVE で参加者以外からのダメージは無効
- シールド破壊（`swordShieldBreak` + 剣攻撃 → 盾クールダウン 100tick）
- ノックバック倍率（次の tick で速度を倍率適用）
- 死亡イベントキャンセル（ドロップ無し・キープインベントリ）
- ブロック設置/破壊制御（`blockPlace` / `blockBreak` / `canBreak`）
- ドロップ禁止（COUNTDOWN / ENDING）、自動食料（`autoFood`）、自然回復禁止（`naturalHealthRegen=false` のとき SATIATED のみキャンセル）、エンダーパール制御（`pearl`）、トーテム判定（`totem`）
- リマッチ / ロビー帰還アイテムのクリック処理
- `ArenaBoundsListener`: アリーナ領域外への移動をスポーンに押し戻す（X/Z ブロック変化時のみ判定）

### 10.7 アリーナ（`ArenaService` 系）

- `AbstractArenaService`: テンプレート毎に 1 インスタンスを遅延生成、`ReentrantLock` で予約を直列化、`MatchRegistry` と二重にガード
- `SimpleArenaService`（FAWE 無し）: 状態切替のみ（ワールド触らず）
- `FaweArenaService`（FAWE 有り）: 解放時にテンプレートの `.schem` をアンカー（min コーナー）にペーストして再生成。schematic 未設定・FAWE 無効・`regenerate-arena=false` なら Simple と同挙動
- `FaweBridgeImpl`: WorldEdit API で `BlockArrayClipboard` 保存 / `ClipboardHolder` ペーストを `AsyncExecutor` 上で実行。初期化失敗（LinkageError 等）は `NoOpFaweBridge` へフォールバック
- `ArenaTemplateStore`: `arenas.yml` の読み書き。`/arena` コマンドで draft → save → enable の流れ。`persistAll` は `LocationUtil.serialize`（`world;x;y;z;yaw;pitch`）形式で spawn を保存

### 10.8 キット適用（`KitService`）

- 公式定義を `kits.yml` から読み込み（Map は小文字キー）
- `apply(player, kit, layout)`: レイアウト優先で装備（GRAY_STAINED_GLASS_PANE はスキップ）、HP・食料・ゲームモード（`forceAdventure` で ADVENTURE / それ以外 SURVIVAL）設定
- `/ekit` の個人レイアウトは `KitLayoutRepository` + `KitLayoutCache`（メモリキャッシュ、試合開始時に DB I/O しない）。`loadSyncIfAbsent` で同期ロード
- `/kit create` は現在の装備から定義を作成して保存

### 10.9 Elo 計算（`EloCalculator`）

- 期待値: `1 / (1 + 10^((相手Elo-自分Elo)/400))`
- Win=1.0 / Draw=0.5 / Loss=0.0
- K 値: 最初の 20 試合は 64、21 試合目以降 32、**上位 10% は 26**（暫定中でも優先）
- レート下限 0
- `RankedResultProcessor`: `tryMarkResultApplied` + 履歴重複チェックの冪等化 → 両者の `ranked_stats` を upsert → `match_history` 挿入 → `daily_ranked_stats` 加算（勝利者のみ kill+1、両者 match+1）
- 引き分けは `drawCountsAsLoss=true`（現状は敗北扱い）

### 10.10 観戦（`SpectatorService`）

- `/spec <player>` / `/specgui`: LOBBY / OPENING_GUI 状態のみ
- 対象マッチが ACTIVE で、両参加者の `spectateVisible` が true のときのみ
- SPECTATOR ゲームモード、他プレイヤーから hide（設定で）、退出時は show してロビーへ
- マッチ終了時は `clearMatch` で全観戦者をロビーへ

### 10.11 FFA（`FfaService` / `FfaListener`）

- `ffa.yml` のアリーナ（初期空）。`/ffa create` 等で管理
- `join()`: メンテナンス・無効・リセット中・状態・キット欠如チェック → `FFA` 遷移 → スポーン → キット適用
- `handleLethal`: 死亡処理（サウンド・セッション統計・非同期 DB 保存）→ キル者はアクションバー更新 → `respawn`
- `respawn`: 即時リスポーン（スポーンへ TP + キット再適用）
- ブロック変更を記録（`blockDiffs`、最大 50,000 件/アリーナ）→ `/ffa reset` で原状復帰（`BlockData` 復元）
- リージョン外移動はスポーンへ押し戻し、`resetting` 中のアリーナは参加不可
- キットルール（シールド破壊 / KB / ブロック / 食料 / 回復 / パール / トーテム）は MatchListener と同様の実装

### 10.12 設定（`SettingsService` / `PlayerSettings` / `/setting` GUI）

`/setting` で変更可能:

- デュエル申請拒否（`acceptDuelRequests`）
- 自動再キュー（`autoRequeue`）
- 観戦許可（`spectateVisible`）
- 他プレイヤーのチャット非表示（`hideOtherChat`）+ **チャットホワイトリスト**（名前をチャット入力で追加 / `clear` で全解除）
- デュエルサウンド（`soundsEnabled`）
- スコアボード（`scoreboardEnabled`）

キャッシュ + 非同期 upsert（`SettingsService.update/unload/flushAll`）。

### 10.13 スコアボード / TAB（`ScoreboardService`）

- 10〜20 tick 間隔の中央タスク（設定値は 10〜20 にクランプ）
- **v1.1.0 からミニマル構成**（太字なし・白/グレー基調）:
  - 常時表示: 鯖名（白・先頭）/ Online / Queue。**鯖 IP（グレー）は常に一番下**
  - 試合中: **`- YOU -`（自分名・自分のチーム色）→ `- OPPONENT -`（相手名・相手のチーム色）** → Kit / Mode / **スコア行（`0 - 0`）** / Time
  - キュー中: Queued: <kit>
  - ※ 旧来の Server / Matches / Lobby 行は削除
- **チーム表示の仕様**: チャット通知は行わず、スコアボードの `- YOU -` / `- OPPONENT -` バナーだけでチーム色を伝える。`- YOU -` の下に自分名（自分のチーム色 = RED なら赤 / BLUE なら青）、`- OPPONENT -` の下に相手名（相手のチーム色）を表示。色は再戦チェーン中ずっと固定（詳細は §10.21 / §20.1）
- **スコア行の仕様**: 左=自分（自分のチーム色で）右=相手（相手のチーム色で）を `自分n - 相手n` の形で表示。最初の試合は `0 - 0`。**再戦ボタンで連続対戦している間だけ**勝つたびに加算される（詳細は §10.21 / §19）
- 各プレイヤーの `scoreboardEnabled` と `scoreboard.enabled` で制御
- TAB ヘッダー/フッター: ヘッダー=鯖名（白）、フッター=鯖 IP + Online 数（グレー）

### 10.14 サウンド（`SoundService`）

- `sounds.yml` をキャッシュ。`play(player, id[, pitch])`
- プレイヤー設定 `soundsEnabled=false` なら再生しない
- `key: none` は無音扱い。`Registry.SOUNDS` で解決失敗時 `ui.button.click` フォールバック

### 10.15 多言語化（`LocaleService` / `MessageService`）

- ロケール正規化: 小文字化 + `-` → `_`
- フォールバック: 要求ロケール → デフォルト → `!key!`
- `MessageService`: MiniMessage デシリアライズ、`<tag>` プレースホルダ（`MessageService.tags("target", name, ...)`）
- チャットプレフィックスなし設計（`general.prefix` は空）

### 10.16 ChatBan / 異議申し立て（`ChatBanService`）

- `issue(target, staff, type, reason, duration)`: `punishments` + `audit_log` に非同期保存、メモリ `activeChatBan` に記録
- `issueDisconnectBan`: 試合中切断（既定 7 日）。`shuttingDown` 中は発行しない
- `isChatBanned`: DB 確認（失敗時メモリ確認）
- チャット（`AsyncChatEvent`）と私信コマンド（`/msg /tell /w /whisper /reply /r /message /pm`）を遮断
- `/objection <reason>`: ChatBan ID 単位で 1 回だけ異議を提出（`objections` テーブル、status=PENDING）
- `/chatunban <player|chatban_id>`: 解除

### 10.17 矢エフェクト（`ArrowEffectService`）

- 2 tick 毎の中央タスクで追跡中の矢を処理（`tracked` マップ）
- 射出時 `ProjectileLaunchEvent` で追跡開始。権限（mem / vip / vip_plus / OP）と設定 `arrowEffect` を確認
- 距離 48 ブロック以内の視聴者にのみパーティクル（プレイヤー毎 40 上限、設定可）
- 矢が死亡・無効・ブロック内に入ったら除去

### 10.18 オリジナルキット / プラン（`OriginalKitService` / `OriginalKitGui`）

- プラン: DEFAULT / MEMBER / VIP / VIP_PLUS（権限で判定）
- 解放スロット:
  - DEFAULT: 22 のみ
  - MEMBER: 13, 21, 22, 23, 31
  - VIP: 中央クロス（r0c4 / r1c3-5 / r2c2-6 / r3c3-5 / r4c4）
  - VIP_PLUS: 44 以外全て
- 月間編集回数制限（`plans.yml`: 10 / 30 / 100 / ∞）、月跨ぎでリセット
- 保存 / 読み込み / 共有コード（8 文字、メモリ保持、`ClientModBridge` は現状 NoOp）

### 10.19 統計・ランキング・プロフィール（`StatsService`）

- `kitStats` / `allKits` / `topElo(kit)` / `topEloOverall` / `topWinStreak` / `topDailyKills` / `topDailyMatches` / `recentRanked`
- `winRateLabel`: 21 試合未満は「計測中 n/21」
- `kd`: wins / max(1, losses)
- `profileMessage`: 区切り線 + MCID + 総試合/勝敗/勝率（計測中表示）/プログレスバー（profile.yml の char/length）/K/D/最高連勝/得意キット
- `nameOf`: オンライン優先、オフラインは OfflinePlayer 名、それも無ければ UUID 先頭 8 文字

### 10.20 実行時フラグ（`RuntimeFlags`）

- `maintenance`: `config.yml` の `plugin.maintenance` から初期化、`/practiceadmin maintenance on|off` で切替 + 永続化
- メンテ中はキュー・FFA・デュエル系を拒否（`rumilance.admin` は例外）

### 10.21 チームカラーと連戦スコア（v1.1.0）

**チームカラー（重複禁止）**

- デュエルでは参加者 index 0 が常に **RED**、index 1 が常に **BLUE**（`MatchSession` の `teamColors`、enum `TeamColor`）
- 2 名しかいないため色の重複は構造上発生しない（重複禁止）
- 再戦チェーンでは参加者順序が同じままなので、**連戦中は自分の色が変わらない**
- チームの通知は**チャットでは行わない**。スコアボードの `- YOU -`（自分名・自分の色）/ `- OPPONENT -`（相手名・相手の色）バナーで表示するのみ（§20.1 参照）

**連戦スコア（0-0 → 1-2 …）**

- `MatchSession` が `seriesWins`（参加者ごとの連戦勝利数）を保持
- 最初の試合（キュー・デュエル申請由来）は `seriesWins` 空 → スコアボードは `0 - 0`
- 試合終了時に勝者へ `addSeriesWin`（`endMatch`）
- **再戦ボタン**で双方がリマッチを承認すると、前セッションの `seriesWinsSnapshot()` を新セッションへ引き継いで `startDuel(...)`（`applySeries`）
- したがって「同じ相手でも、再戦を押して連続で戦った場合のみ」スコアが加算され、キューや新規申請で組み直した場合は 0-0 に戻る
- スコアボード表示: 自分から見て左=自分の勝利数（自分の色）、右=相手の勝利数（相手の色）。例: RED の自分なら `§c1 §7- §90`、BLUE の自分なら `§91 §7- §c0`

## 18. トラブルシューティング・注意点

| 症状 | 原因・対処 |
|---|---|
| 「FastAsyncWorldEdit/WorldEdit not detected」警告 | FAWE/WE 未導入。導入するか `config.yml` の `fawe.enabled: false` |
| 試合が始まらない | `arenas.yml` に enabled な DUEL テンプレートがあるか確認。ワールド名・座標・スポーンが正しいか |
| キューに入れない | プレイヤーが LOBBY/OPENING_GUI 状態か、キットが enabled か、メンテナンス中でないか |
| DB エラー | `database.yml`（標準 SQLite）とデータフォルダの書込み権限。SQLite は `data/` ディレクトリ自動作成 |
| 起動時にプラグイン無効 | `initializeDatabase` 失敗時は「Failed to initialize the database. Disabling RumilancePractice.」+ スタックトレース。thin jar を使用していないか（`-thin` 付きは DB ドライバなしで失敗する） |
| コマンドが「なんかエラーが発生しました」系 | サーバーコンソール / `logs/latest.log` のスタックトレース（`Caused by:`）が必要。ログを確認して `RumilancePractice` 行と `Exception` 行を探す |
| 表示が `!key!` になる | 翻訳キー不足。`lang/` のロケールファイル確認 |
| 効果音が鳴らない | `sounds.yml` の key が `none` / プレイヤー設定の Duel Sounds OFF / キー名が 1.21 に無い |
| 設定変更が反映されない | `/practiceadmin reload`（kits / arenas / ffa / lobby / sounds）。DB やプラグイン全体は再起動 |
| 切断でいきなり ChatBan | 試合 ACTIVE 中の切断は既定 7 日 ChatBan（`rumilance.punishment.bypass` で回避可）。サーバー停止時は発行されない |

### 現状の未実装・注意点（コード調査によるメモ）

- `general.unknown-error`（「予期しないエラーが発生しました。管理者に連絡してください。」）は言語ファイルに定義済みだが、**Java コードからは参照されていない**（Bukkit 側の汎用エラーメッセージが出ている場合はサーバーログのスタックトレースが手掛かり）
- `gui.yml` / `profile.yml` の一部項目 / `hooks.placeholderapi` / `ffa.yml` の settings 群 / `reconnect-grace-seconds` は現状コード上で使用されていない（将来用）
- `ClientModBridge` は常に NoOp
- スコアボードの「Lobby」行は描画のみ（表示名タグの衝突回避は `§` コードで行っている）
- `QueueKitGui` / `StatsKitGui` などの GUI タイトルはローカライズされていないものがある（一部日本語・英語混在）

## 20. UI・表示仕様詳細（v1.1.0）

ここでは「画面に何がどう表示されるか」をコード準拠で細かく記す。配色表記はチャット書式コード（`§c`=赤、`§9`=青、`§7`=グレー、`§f`=白、`§e`=黄、`§a`=緑、`§b`=水色、`§d`=ピンク、`§6`=金）。

### 20.1 スコアボード（状態別 完全図）

スロット行数: 15 行（スコア値 15〜1 で上から降順ソート）。更新間隔: 既定 20 tick（10〜20 にクランプ）。

**ロビー / それ以外（キューでもマッチでもない）**

```

§7Queue: §f2
§r                     ← 空行
§7play.example.com    ← scoreboard.server-ip（グレー・常に一番下）
```

**キュー中（上記に +1 行）**

```
§fRumilance
§7Online: §f12
§7Queue: §f2
§r
§fQueued: §7nodebuff   ← キュー参加中のみ
§r                      ← 区切り
§7play.example.com    ← 一番下
```

**試合中（COUNTDOWN / ACTIVE / ENDING）**

```
§fRumilance
§7Online: §f12
§7Queue: §f2
§r
§7- YOU -
§cSteve                ← 自分の名前（自分のチーム色。RED なら §c 赤 / BLUE なら §9 青）
§7- OPPONENT -
§9Alex                 ← 相手の名前（相手のチーム色）
§fKit: §7nodebuff
§fMode: §7RANKED
§c1 §7- §90            ← 連戦スコア（左=自分の勝利数・自分の色 / 右=相手の勝利数・相手の色）
§7Time: §f42s          ← ACTIVE 開始からの経過秒（COUNTDOWN 中は表示なし）
§r                      ← 区切り
§7play.example.com    ← 一番下
```

- `- YOU -` / `- OPPONENT -` のヘッダーはグレー、名前のみチーム色
- チーム色の割当: 参加者 index 0 = RED、index 1 = BLUE（重複なし・再戦チェーン中は不変）
- 連戦スコア: 初戦は `0 - 0`。**再戦ボタンによる連続対戦のみ**加算（§10.21）

**TAB ヘッダー / フッター**（`scoreboard.tab-header-footer: true` 時）

- ヘッダー: `§fRumilance`（server-name、白）

## 21. v1.2.0 設計: `/ekit` リニューアル（実装済み）

> ユーザー提示の仕様を実装した際の設計メモ。実装時の判断は §21.12 に追記。

### 21.1 全体フロー

```
/ekit
 └─ Kit一覧GUI
      ├─ キットをクリック → 中央の板ガラスに代入
      ├─ 「選択」(黄緑の板ガラス) を押す
      │     ├─ 通常キット → EditKitGUI（縦5×横9）
      │     └─ オリジナルキット → OriginalKitGUI（縦5×横9）
      └─ Kit一覧の最後には常に赤い紙「オリジナルキット」
```

- Kit一覧GUI: 各キットのアイコン + 最後に赤い紙「オリジナルキット」。クリックで中央の板ガラスに代入。「選択」で対応GUIへ。

### 21.2 EditKitGUI（通常キット編集、縦5行×横9列 = 45スロット）

| 行 | 内容 |
|---|---|
| 1行目 | 1列目=装飾 / **2〜5列目=ヘルメット・チェストプレート・レギンス・ブーツ** / 6列目=オフハンド / 7〜9列目=装飾 |
| 2〜4行目 | インベントリ（27スロット） |
| 5行目 | ホットバー（9スロット） |

- アイテムの位置（装飾除く）を変更することで**開始時のアイテム配置**を設定できる
- 現行の `EditKitGui` は既にほぼこの構造（防具行 + ホットバー）なので、レイアウト調整 + 選択画面の追加が中心

### 21.3 OriginalKitGUI（オリジナルキット選択、縦5行×横9列）

- **紙1つごとに1つのオリジナルキットを割り当てられる**（現行は1人1キットのみ → 複数化が必要、§21.12）
- 5行9列目（スロット44）は常に空（紙もバリアも置かない）

### 21.4 プラン別スロット配置

| プラン | 紙の位置 | 紙以外（5行9列目除く） |
|---|---|---|
| `rumilance.user.def` | 3行5列目（スロット22）のみ | 全バリア。**SVIP以上で解放される欄は「SVIP以上で開放」、VIPで解放される欄は「VIPで開放」** と記載 |
| `rumilance.user.svip` | 1行5列（4）/ 2行4〜6列（12,13,14）/ 3行3〜7列（20〜24）/ 4行4〜6列（30,31,32）/ 5行5列（40） | 全バリア「**VIP以上で開放**」 |
| `rumilance.user.vip` | 5行9列目以外の全て | バリアなし |

> 現行の解放パターンと比較: def=22 は現行DEFAULTと一致。svipの十字パターンは現行VIPと一致。vipの全開放（44除く）は現行VIP_PLUSと一致 → **プラン名の再編**（§21.12で確認）。

### 21.5 紙クリック時の挙動（編集開始）

| プラン | 紙クリック時 |
|---|---|
| def / svip | **確認画面「本当にこのキットを編集しますか？」**。説明欄に「今月の残り編集可能回数 : %can_edit_original%」（プレースホルダは実残数に置換） |
| vip | 確認画面なしで即次へ |

- 「はい」を押すと **ユーザーのインベントリが一度 clear される**
- **初めてそのオリジナルキットを編集する場合**は、インベントリ（もしくは選択GUI）に選択肢を表示:
  1. **「新しくキットを作成する」**（アイコン: 紙）→ （装飾以外）空のキット編集GUIを開く
  2. **「公式キットをコピーする」**（アイコン: ダイヤモンド）→ 公式キット一覧を開く → 好きなキットを選択するとインベントリの中身等がコピーされてオリジナルキットになる

### 21.6 OrPlusGUI（キット編集 + ユーザーインベントリ表示）

- 通常のキット編集画面と同じ画面だが、**ユーザーのインベントリも表示される形式**（通称 OrPlusGUI）
- ユーザーのインベントリには以下のカテゴリアイテムが存在:
  - **「武器/防具」** = ネザライトのチェストプレート
  - **「サブアイテム」** = 水バケツ
  - **「ブロック」** = オークの板材
  - **「ポーション」** = 治癒のスプラッシュポーション
- **各カテゴリにはOPコマンドでアイテムを追加できる**
- インベントリ内にある**追加されたアイテムをクリックするとGUI内にそのアイテムが出現**する（キットに追加）
- 装備等は**強制的に装備の欄に上書き**され、インベントリに入れることはできない
- **カテゴリ内アイテムが28個以上**の場合、インベントリに入り切らないためページング:
  - 次ページがあれば **左から9番目のホットバー**に「次のページへ」（黄緑の板ガラス）
  - 前ページがあれば **左から1番目のホットバー**に「前のページへ」（黄緑の板ガラス）

### 21.7 武器/防具のエンチャント選択（特殊仕様）

1. 「装備又は武器」を選択 → **エンチャント本がインベントリ内に全て列挙**される
2. 付けたいエンチャントの本をクリック → **様々なレベル（バニラの範囲）のエンチャント本**が出てくる（例: ダメージ増加 = I〜V）
3. 付けたいレベルのエンチャ本をクリック → **そのエンチャントが付く** → エンチャント一覧画面に戻る
4. もう一度エンチャント本をクリック → **付いているそのエンチャントを外す**（レベル問わず）
5. **バニラ尊重**: 「本来そのアイテムにつけられないエンチャント」「本来不可能なエンチャントの組み合わせ」「本来存在しないレベルのエンチャント」は不可。漏れがないように実装
6. エンチャント不要なら **ホットバー5番「続行」** でエンチャントなしの状態でキットに入れる

### 21.8 ポーション選択（特殊仕様）

- ポーションを選択したら、**効果の強さや持続時間などバニラサバイバルである範囲**の選択肢が表示される

### 21.9 追加制約
