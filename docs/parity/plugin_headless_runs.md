参照 = 実 QuantumBOT(Fabric + Quantum's PvP Practice v1.18, difficulty 2)。
プラグイン側 = NARENA の練習BOT を `narena-harness`(開発フラグ `-Drumilance.harness=true`)で
**普通に戦わせた**だけ。シナリオ固定・対象凍結・特別ラウンドは一切なし。

## 計測環境(両者で同じ条件にそろえたもの)

| 計測 | qlog 1行/毎tick(`[q] ... anc= ct= pc= hit=`)+ 距離バンド d2/d3/d6/d9 | `[N Arena][BotMatch]` trace(0.1s)+ samples(0.1s) |
| 長さ | 420 秒 | 145〜150 秒 × 複数本 |

### 今回 map から拾って直したもの(すべて `quantum/` の実装が根拠)

1. **アンカーの可視範囲**: `mark/mark_main` は `loc1`(=アンカーの実ブロック位置)マーカーにしか
   `usable` を付けず、その条件が「ボットの目から **4.6 ブロック以内**」。8 ブロックは
   *マークを立てる*半径にすぎない。→ `anchorReach = 4.6`。
   6〜9 ブロックからアンカーを撃っていたのが、参照に無い「6〜9 滞在 24%」の主因だった。
2. **クリスタルの可視範囲は 3.5 ブロック**(同じ `mark_main`)。以前は 9 ブロックまで置いており、
   クリスタル 21.9/min(参照 5.3)になっていた。→ 3.5 で参照とほぼ一致(5.0〜6.6/min)。
3. **追いパールは相手のブロックで止まる**: `ray/cast2 → ray/pearlstep` は
   「`@a[tag=xlib_target,dx=0]` になったら return」= 着地点は相手の足元。以前は 15 ブロック上限で
   6 ブロック手前に着地し、そこから 6〜9 を *歩いて* いた(滞在 24%)。→ 上限を外して一気に着地。
4. **逃げパールは 4.6〜10 ブロック**(`crystal/passive/main` の 8..10 / 8..15 分岐)。
   近距離(=マーカーが立っている=戦闘中)からは投げない、が正しい読み。
5. **立ち位置 3〜4.5 ブロック**(`g1gc/movement` は crystal マーカーが 2.5〜3.5 の位置に来るよう
   動き、`move forward` はアンカーの各タイマー中は拒否される)。

### 残差は「BOT が濃すぎる」= 相手(ハーネス)側の問題でもある

参照の 420 秒を1tick単位で数え直すと、**アンカー/クリスタルの機構が動いているのは全 tick の
20.4% だけ**で、連鎖の中央値は 11 tick・間の空きは中央値 19 tick/平均 69 tick。つまり実機の BOT は
「12 tick の連鎖 → 1 秒前後の間 → また連鎖」を繰り返している。こちらは 1 連鎖あたり 1 発の剣＋
1 連鎖までは同じだが、**再エンゲージまでが 1 秒(逃げ→追いパール)しかなく、連鎖が途切れない**。
b22 で逃げ後に 2 秒の passive(徒歩で戻る・追いパール禁止)を入れて周期を 3 秒まで伸ばしたが、
参照の 5.25 秒(剣 80 発 / 420 秒)にはまだ足りない。

実機の 5 秒周期は「相手(プレイヤー)が動く・殴る・跳ぶ」ことでマーカーが頻繁に無効化される為で、
**棒立ちで殴ってこない偽プレイヤー相手では原理的に再現しない**。この差は BOT のロジックではなく
相手モデル側の差なので、次のどちらかで詰める:

- ハーネスの相手を「普通に動く相手」(前進/後退/ジャンプ/ノックバック)にする ← 本筋
- もしくは BOT 側の再エンゲージ周期を `PASSIVE_ESCAPE_WINDOW_MS`(現在 2000ms)で調整する

`PASSIVE_ESCAPE_WINDOW_MS` を 0 にすると b18 の値(滞在 <=6 33.2% / アンカー 31.4/min)、
2000 で b22(21.9% / 23.2)になる。参照は 37.3% / 18.1 なので、相手モデルを直したうえで
この値を詰めるのが正しい順序。

## 2026-09-15 (2): 「ハーネスのせいか、BOTのせいか」の切り分けと、参照の本当の周期

### 結論: 相手(ハーネス)は原因ではない — 原因は BOT 側の「状態機械」が丸ごと無いこと

参照側の相手が何だったのかを `docs/parity/README.md` と `tools/qlog-datapack` で確認した:

- 参照の相手は `/playerspawn target1` で出した**ただのフェイクプレイヤー**(`quantum:miscellaneous/tags` が
  `xlib_target` を付けるだけで、ピン留めも AI も無い)。移動も攻撃もしない、こちらの `HarnessBot` と同型。
- ただし `qlog:keepalive` が毎tick
  `effect give @a[tag=xlib_target] resistance 2 1 true` + `regeneration 2 3 true` を与えて**延命している**
  (README: 「相手HP 20.0 → 最小 2.0、実ダメージ 18」= 抵抗と再生込みで 20→2 まで削られている)。
- 参照のBOT自身は**自分のアンカー爆破で自分を削っている**。run8 の 34 秒アンカー窓(下記)で
  HP 20.0 → 3.7 まで落ち、403 秒全体で hp 平均 16.8 / 最小 0.0 / トーテム POP 3 回。

つまり「こちらの偽プレイヤーが動かない/殴らないから件数が増える」は**言い訳にならない**。
参照も同じ棒立ち相手で、しかも 145 秒で測ったこちらの方が**行動回数が 2〜3 倍**だった。
差分は BOT の内部にあり、正体は map の**状態機械**である。

### map の実装(crystal = mode 2)で確定したこと

1. **`quantum:crystal/tick` は `state` で分岐する**:
   `unless state 1..2 → bin/13`(PASSIVE = `crystal/passive/main`)、`if state 1..2 → bin/27`(ATTACK =
   アンカー連鎖 + クリスタル + 剣 + 追いパール)。
   アンカー/クリスタルは**ATTACK のときだけ**動き、PASSIVE では 1 本も撃たない。
2. **`state` は `eval` から毎tick再計算**(`eval/biased`):
   `eval = (自分のHP − 相手のHP) × 20`(相手に再生効果があれば `+50`)
   `+ eval_hit × 80`(`can_hit` なら +2、不可なら −1。= `(botHP - targetHP) * 20` が支配項)。
   `eval <= -1` で **即 PASSIVE**、`bin/29` の 30 % ロールで攻撃継続。
   → 「HP で負けている間は引く」= 参照の周期の正体。
3. **run8 の 34 秒窓は純アンカー連鎖**: d≈3.3 固定・`hit=0 pc=0`・`place→charge→爆発→次place` が
   12 tick(0.60 s)ジャスト。この 34 秒で HP は 20.0 → 3.7(自分の爆風)。
4. 403 秒の内訳: ATTACK(アンカー/クリスタルのタイマが動いている)は **22.5 %**、
   PASSIVE が **77.5 %**。アンカー設置は 403 秒で 117 回 = 17.4/min(既存の 420 秒表 18.1 と一致)。
5. `xaniclelib:anchor/explosion` は**バニラ爆発ではない**: `setblock ~ ~ ~ air` + `swing once` +
   `quantum:bad_respawn_point` エンチャント付きレンガを持った armor_stand を出すだけで、
   **島のデータパック内に `damage` コマンドが1つも無い**(`xaniclelib/anchor/` 全ファイル)。
   実際の爆風(ダメージ/ノックバック)は**練習MOD(HEhero)側**が `explosionNoBlockDamage` 設定で出している。

### 分かったこと

1. **eval の +225 は「ATTACK 中のみ」**。`eval/tick` は `if score @s state matches 1..2` の下で加算し、
   その直後の `eval/biased` が state を決める。したがって **PASSIVE に入る閾値は
   `(botHP − targetHP) × 20 + 50 + hit ≤ −226`**、つまり 20 HP の相手なら自 HP 6.25 以下。

   **遠距離(ターゲットが 15 ブロック以遠)で +225 が消えることも PASSIVE の主要因**。
2. **逃走パールは分岐の外**。`bin/13` の構造上、ATTACK 中でも 8 ブロック以内ならパールで離脱する。

4. 自爆ダメージは `SELF_BLAST_RAW 2.1`(k² 減衰)で参照の 0.68 HP/連鎖にほぼ一致する見込み
