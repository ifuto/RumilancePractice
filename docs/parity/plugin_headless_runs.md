# プラグイン側BOT ヘッドレス実測ログ(石100床・通常戦)

参照 = 実 QuantumBOT(Fabric + Quantum's PvP Practice v1.18, difficulty 2)。
プラグイン側 = NARENA の練習BOT を `narena-harness`(開発フラグ `-Drumilance.harness=true`)で
**普通に戦わせた**だけ。シナリオ固定・対象凍結・特別ラウンドは一切なし。

## 計測環境(両者で同じ条件にそろえたもの)

| 項目 | 参照(QuantumBot) | プラグイン(NARENA) |
|---|---|---|
| 床 | 石 94 ブロック(y=-37..56 付近) | 石 **100** ブロック(`ground 40 100` → 81×81, y=-37..63) |
| 相手 | 対戦相手プレイヤー(自動で戦う) | 偽プレイヤー `HarnessBot`(通常の join→countdown→match) |
| ラウンド | マップ標準(通常戦・自動開始) | 通常戦(難易度 INTERMEDIATE = map difficulty 2) |
| 計測 | qlog 1行/毎tick(`[q] ... anc= ct= pc= hit=`)+ 距離バンド d2/d3/d6/d9 | `[N Arena][BotMatch]` trace(0.1s)+ samples(0.1s) |
| 長さ | 420 秒 | 145〜150 秒 × 複数本 |

距離バンドは参照側 qlog に追加した計測列(相手との距離がそれぞれ 2/3/6/9 ブロック以内か)。
プラグイン側は samples の座標と相手の座標から `tools/fight_profile.py` が同じ形に集計する。

## 参照(実 QuantumBOT)の実測値 — 420 秒 / difficulty 2

```
距離滞在: <=2:4.6%  <=3:3.5%  <=6:37.3%  <=9:2.5%  >9:52.1%
行動                    回数    /min   距離バンド内訳
pearl throw          345    49.2   中央ギャップ  1.00s | <=2:  1%  <=3:  1%  <=6: 29%  <=9:  3%  >9: 66%
anchor place         127    18.1   中央ギャップ  0.60s | <=2: 21%  <=3: 10%  <=6: 69%
anchor charge        128    18.3   中央ギャップ  0.60s | <=2: 27%  <=3:  5%  <=6: 68%
crystal place         37     5.3   中央ギャップ  8.75s | <=2: 49%  <=3: 19%  <=6: 27%  <=9:  5%
melee swing           80    11.4   中央ギャップ  0.50s | <=2: 46%  <=3: 54%
手持ち: ender_pearl 76.5% / totem 7.2% / glowstone 5.7% / respawn_anchor 5.5% / end_crystal 2.7% / diamond_sword 2.3%
```

読み取れること(これがプラグイン側の設計根拠になった):

1. **アンカーは近距離でも撃つ**。127 回のうち 31% が 3 ブロック以内、69% が 3〜6 ブロック。
   → 「近接中はアンカー封印」は誤り。map `bin/27` の `cannot_anchor`(殴った直後の hitcd 6..1 は
   `g1gc/anchor_tick` が return)が本当のゲート。
2. **パールは距離を見ない**。1 秒毎(中央ギャップ 1.00s)に投げ、2 ブロック以内でも 1% は投げる。
   1 ブロック以内だけは 0(着地点が相手のヒットボックス内になるため)。
3. **剣は 3 ブロック以内のみ**、中央ギャップ 0.50s(= hitcd 相当)。
4. 立ち回り: 半分以上の時間を 9 ブロック以遠で過ごし、パールで間合いを詰める。
   → 近接に張り付いたままの相手(こちらの偽プレイヤー)では件数の絶対値が変わるため、
   比較は「距離バンド内訳」で行う必要がある。

## 直したこと(実測 → 原因 → 修正)

| 症状 | 原因 | 修正 |
|---|---|---|
| 近接中はアンカーが 1 回で止まる | `dist <= 3.0` で engage を封印していた | map `bin/27` の `cannot_anchor` を自分のスイング間隔で再現(v1.76.15) |
| 相手の hurt frame 待ちにしたが窓が開かない | 偽プレイヤーはプラグイン独自のダメージ登録で i-frame が付かない | 同上(自分の hitcd を窓の基準に) |
| パールが 1 回で止まる | `findPearlLanding` が 2.0 ブロック未満の候補を全部捨てていた | 近接ホップも許可(v1.76.16) |
| パールの着地が相手の体内 | 近接時に「0.9 ブロック以内の着地」を弾いていた | map の ray は相手ヒットボックスで止まるので、そのまま採用(v1.76.15) |
| アンカーが 33 秒で停止 | アンカー16 + グロウストーン64(4個/チャージ)の弾切れ | パールと同じ補充(v1.76.16) |
| 剣ログが 60 秒で途切れる | chatter(swing/hit)バジェット 300 件 | 3000 件に拡大(v1.76.14) |

## run7(1.76.18)の実測 — 参照と同じ土俵での比較

```
行動               何/分      参照(全体)   参照(距離バンド内)
pearl              60.0       49.2         31(≤6ブロック滞在 191 秒あたり)
anchor place       29.8       18.1         40(同上)
crystal place      13.7        5.3         11(同上)
melee swing        74.9       11.4        141(≤3ブロック滞在 34 秒あたり)
手持ち: sword 42.7% / pearl 27.0% / glowstone 11.7% / end_crystal 8.4% / bow 6.4% / anchor 3.8%
```

- パール: 受動(離脱)+ チェイスで 60/min。参照 49.2/min の 1.2 倍まで来た(合計は `pearlcd` 20t 共有)。
- アンカー: 連鎖の再開間隔を実測値(約1.4秒)に合わせて 82.8 → 29.8/min。参照の 6 ブロック以内
  レート(40/min)と全体値(18/min)の間に収まった。
- クリスタル: 13.7/min は参照の「バンド内 11/min」とほぼ同水準(全体 5.3/min に対しては 2.6 倍)。
- 剣: 74.9/min は参照の全体値(11.4)より多いが、これは**相手が押し返さない**ためで、
  参照は 91% の時間を 3 ブロック以遠で過ごす(こちらは 99.9% が 2 ブロック以内)。
  参照の「3 ブロック以内滞在あたり」は 141/min なので、剣の間隔そのものは同等(7 tick = 350 ms)。


## 参照(実 QuantumBOT)の「距離バンド別」実測 — 420 秒・difficulty 2

`/tmp/ref_dist_run.log`(8409 tick, 420.45 s, d2/d3/d6/d9 付き qlog)から。

| 距離 | 滞在 | 割合 | anchor place | pearl | swing |
|---|---|---|---|---|---|
| ≤2 | 19.4 s | 4.6% | 47 (145/min of dwell) | 3 | 37 (114/min) |
| ≤3 | 14.7 s | 3.5% | 31 (131/min) | 5 | 43 (176/min) |
| ≤6 | 156.9 s | 37.3% | 39 (14.9/min) | 100 | 0 |
| ≤9 | 10.5 s | 2.5% | 2 (17.1/min) | 10 | 0 |
| >9 | 218.9 s | 52.1% | 2 | 227 (62.2/min) | 0 |
| **合計** | 420.5 s | | **121 (17.3/min)** | **345 (49.2/min)** | **80 (11.4/min)** |

読み取れること:

- **アンカーは「近距離にいる間だけ、ラダー全速(約0.4秒/連鎖)」**。2 ブロック以内の滞在 19.4 秒で
  47 連鎖 = 145/min。参照は 6 ブロック以内に 45% しか居ないので、全体では 17.3/min になる。
  「1 秒に 1 回」でも「1.7 秒に 1 回」でもなく、**滞在時間が先、頻度は従属**。
- **剣は 3 ブロック以内のみ**、しかも 0.34 秒間隔(7 tick)の全速。全体 11.4/min は滞在が 8% しか
  ないため。バンド外では 1 回も振っていない。
- **パールは >9 ブロック滞在の 62/min**(=ほぼ pearlcd 20 tick の上限)。近距離ではほとんど投げない
  (≤2 は 1%)。
- つまり参照の rhythm は「遠くでパールを投げ続けて接近 → 近づいた瞬間だけアンカー/剣を全速 →
  すぐ離れる」。プラグイン側が 49% を 2 ブロック以内で過ごすのが、頻度差の根本原因。

## 残差

- 剣 15.0%(ref 2.3%)と melee 77/min(ref 11.4)は**滞在分布**の従属変数。参照は 3 ブロック以内に
  8% しか居ないので、まず接近→離脱の rhythm(バースト)を合わせる必要がある。
- パール 59.6/min(ref 49.2)。参照は近距離では投げない(≤2 で 1%)ため、受動パールの距離ゲート
  (≤8 ブロック)を「ピンチ時のみ」に寄せる余地がある。
- アンカーは 1.76.19 で 29.8 -> 20.3/min(ref 17.3、目標帯 16.5-18)。

## 残っている差(2026-09-15 時点)

- パール: run5 まで 0.4/min。v1.76.16 で 1 秒毎に戻る見込み(参照 49.2/min)。
- アンカー: run5 の 6.6/min(停止込み)。v1.76.16 以降は周期 0.7 秒 × 途切れなしが期待値で、
  参照の「距離バンド内」レート(≤6ブロック滞在 191 秒あたり 100 回 = 31/min)と比較する。
